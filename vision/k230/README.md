# K230 五色方块识别

适用目标：亚博 K230 豪华版及配套摄像头，使用 TF 卡上已有的 `libs/PipeLine.py`。
入口沿用 `three_color_blocks.py`。屏幕和控制台可识别红、绿、蓝、黄、紫五色。整机联调时可启用 `UART_ENABLED`。现有 MSPM0 V1 分拣协议只有红、绿、蓝三个投放位，配套的 `robot_link.py` 会把黄色、紫色上报为 `UNKNOWN`，表示视野中有未配置投放位的目标。
识别结果是 640×480 图像的像素坐标，不是机械臂坐标。默认阈值尚未现场标定。

G3519 课堂接线与 UART 回显见[同学调试手册](../../output/pdf/Robot1机械臂同学调试手册.pdf)。旧 G3507 台架的 `@T` 视觉脚本另见[台架视觉说明](README_G3507_bench.md)。

## 运行

1. 在 CanMV IDE 连接 K230，停止原有程序，避免两个程序同时占用摄像头。
2. 保留原有 TF 卡内容，特别是 `libs` 目录。打开 `three_color_blocks.py`，直接运行；首次不替换开机 `main.py`。
3. 默认 `MODE = "detect"`。屏幕显示工作区域、标定状态和帧率。每个方块通过颜色、形状和稳定判定后才显示框与中心坐标。粗框标出当前跟踪目标，其他稳定方块使用细框。目标丢失时立即清除标注。
4. IDE 停止按钮或 KeyboardInterrupt 结束程序并调用配套 PipeLine 的资源清理。

G3507 固定点 V1 整机接线和操作见项目 `docs/wiring_v1.md`、`docs/testing_v1.md`。启用 UART 前将 `robot_link.py` 复制到板卡 `/sdcard/`，设置 `UART_ENABLED = True`。IO9 为 TX、IO10 为 RX，115200。
主控发送 `OBS,批次号` 后，视觉跟踪和稳定计数会重新开始。UART 使用带版本、批次、序号和异或校验的 V1 帧，不使用下文的控制台打印格式。

若出现 `No module named libs.PipeLine`，先恢复与该板固件配套的 TF 卡库文件。现有本地参考位于
`D:/DevProject/MSPM0G3507__car/K230_Vision/libs/PipeLine.py`，但不要直接覆盖板上不同版本的库。
首次启动失败时保存完整报错；如果显示或相机资源没有释放，重启板卡后再试。

## 现场标定

程序顶部包含所有可调参数。标定和识别时保持相同摄像头姿态、距离、背景与光照，先让机械臂静止。
软件没有锁定曝光或白平衡，自动调节与环境变化仍可能影响阈值。

1. 把 `MODE` 改为 `"calibrate"`，`CALIBRATION_COLOR` 设为 `"RED"`。
2. 将红色方块的一块均匀表面完全覆盖中央 40×40 白框。不要把边缘、背景、阴影分界或强反光混入框内。
3. 保持至少 1 秒，控制台会周期打印 `SUGGEST,RED,(六个整数),(取样区域)`。
4. 六个整数依次是 LAB 的 L 下限/上限、A 下限/上限、B 下限/上限。程序使用最近 20 帧的 10%/90% 分位数中位数，并增加少量余量；这些是建议值，不会自动修改程序。
5. 将建议值填入 `COLORS` 对应行。用 `GREEN`、`BLUE`、`YELLOW`、`PURPLE` 分别重复取样，每换一种颜色就停止、修改 `CALIBRATION_COLOR`、重新运行。
6. 改回 `MODE = "detect"`，逐个颜色测试，再测试五色同框、相近底色和空工作台。通过后可将 `CALIBRATED` 改为 `True` 记录标定状态。

`MODE = "preview"` 提供不带标注的画面，可供 IDE 工具取样。
采样算法不能判断白框内是否真的是方块。背景也能产生建议值，必须由操作者检查取样内容。

## 相近底色与花纹桌面

检测时先取工作区四角小块的 LAB 中位数。如果至少三个角的颜色接近，就用它们估计桌面底色。程序在图像副本中屏蔽该色域，再搜索五种颜色的连通区域。因此，即使黄色方块放在黄纸上，只要亮度 L 或色度 a、b 有一个通道能将两者区分开，程序也能单独提取方块。蓝紫、黄绿的候选色域有重叠时，还会按候选像素在 a、b 平面中的色调方向判别。

- 尽量让 `WORK_ROI` 的四角落在工作台上。默认 `BG_TOLERANCE = (6, 6, 6)`，依次对应 L、a、b 三通道允许的背景波动。方块被一起滤掉时，用采样模式比较方块和桌面，只缩小有可测差异的通道容差，再检查空台误报。
- 花纹桌面四角颜色各异时，可用 `CALIBRATION_COLOR = "BACKGROUND"` 分别采样容易粘连的底色，将建议阈值写入 `BACKGROUND_LAB = ((L低, L高, a低, a高, b低, b高),)`。多种底色可填多组六元组。这些范围在每帧都被排除。若底色范围也包含方块的全部颜色，需换底垫或改变照明角度以产生可见色差。

## 工作区域和稳定判定

- `WORK_ROI = (x, y, 宽, 高)`：限定工作台区域，尽量排除绿色机械臂。灰框附近被裁切的色块会被排除，不要把方块贴着区域边缘摆放。
- `MIN_PIXELS`、`MIN_AREA`：过滤小杂点。方块较远时可适当减小，减小后重新检查背景误检。
- `MIN_ASPECT`、`MAX_ASPECT`、`MIN_FILL`：按投影形状筛选，只能找出近似方块的色块，不能证明其三维形状。
- `MAX_AREA_FRACTION`：排除占工作区域过大的彩色背景，默认上限 35%。
- `COLOR_CONFLICT`：同一区域匹配多个颜色，冲突区域不输出为目标；其他不冲突的目标仍可识别。
- `CLUTTER`：有效候选超过 30 个，本帧不选择目标。先收窄工作区和阈值，而不是直接增大数量限制。

首次选择像素数最多的候选。后续优先跟踪附近同色、尺寸相近的目标，避免两个方块面积波动造成来回切换。
如果无法区分两个近邻候选，则取消本帧目标，并重新累计稳定时间。

`STABLE` 同时要求至少 5 帧和累计 250 ms，中心相对本段起点偏移不超过 8 像素，包围框面积比例不超过 1.5。
目标丢失、颜色变化、帧间隔超过 400 ms、位置或尺寸变化过大时重新累计。
这只是图像稳定判定，不代表已完成抓取标定，也不能保证遮挡或交叉运动后的物体身份。

## 控制台输出

检测模式约每 200 ms 输出一次：

```text
DETECT,RED,320,240,1600,1
NONE
```

字段为消息类型、颜色、中心 x、中心 y、匹配像素数、稳定标志（0 或 1）。坐标原点在左上角，x 向右、y 向下。
输出是当前帧原始中心坐标，没有平滑。`NONE` 表示当前没有可选目标，包括丢失、颜色冲突和跟踪歧义。
启动信息注明标定状态及分辨率；它与旧 OpenMV 的 160×120 `BLOCK` 协议不同，不能直接给旧主控程序使用。

## 测试与验收

电脑端回归测试：

```powershell
python -m pytest tests/test_k230_vision.py -q
```

测试覆盖候选过滤、冲突、跟踪、取样和配置校验。安装 OpenCV 和 NumPy 后也会运行像素回归，包括五色同框、近色桌面和花纹背景。主机用 RGB565 量化和 OpenCV 近似板上的 LAB 转换，实际帧率和现场色域仍需上板测量。

上板后逐项记录实际结果，目前均待实测：

| 场景 | 检查内容 |
| --- | --- |
| 空工作区保持 10 秒 | 不应持续出现稳定目标 |
| 红绿蓝黄紫分别放入 | 颜色标签正确，中心落在方块上，静止后稳定 |
| 五色同框 | 五个标签正确，选定目标不因面积小幅变化跳转 |
| 黄色放在黄纸上、紫色放在近紫底色上 | 静止后只框方块，移走后无稳定目标 |
| 两个同色方块 | 选定目标持续跟踪；相互靠近或遮挡后允许重新确认 |
| 缓慢移动与移出 | 移动超过稳定窗口后重新等待，移出后清除目标 |
| 区域边缘与绿色机械臂 | 区域外不识别，裁切目标不稳定输出 |
| 改变光照与距离 | 记录误检、漏检和实际 FPS，必要时重新标定 |
| 停止后重新运行 | 相机和屏幕能重新初始化 |

每次记录固件版本、摄像头型号、程序参数、灯光条件、现象和报错。机械臂上的摄像头随关节运动，后续接入抓取前还需固定观察姿态或处理相机运动。
