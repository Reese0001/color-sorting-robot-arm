# 三色分拣机械臂：完整代码使用入口

本包用于 K230 豪华版 + MSPM0G3507 + BusLinker V2.5。机械臂共五个舵机：20 kg·cm 底座、25 kg·cm 第一俯仰关节、HTD-35H 两只、HTS-21H 夹爪一只。

实现流程：在固定抓取点放一个红/绿/蓝方块 → K230 识别 → MSPM0 控制抓取 → 放入对应区域 → 回到观察姿态。需要先完成颜色标定和七个姿态的实物示教。程序没有预填机械角度，也不支持任意位置抓取。

## 1. 完整代码在哪里

| 文件 | 用途 | 运行位置 |
| --- | --- | --- |
| `firmware/mspm0/main.c` | 硬件初始化、串口中断、PWM、看门狗 | 编译后烧到 MSPM0 |
| `firmware/mspm0/robot.c` | 总线舵机协议、平滑运动、示教、分拣状态机 | 编译后烧到 MSPM0 |
| `firmware/mspm0/robot.h` | 控制核心接口 | 随固件编译 |
| `firmware/mspm0/robot_config.h` | 舵机限位、ID、抓取窗口 | 修改后重新编译 |
| `firmware/mspm0/robot.syscfg` | 引脚、时钟和外设配置 | TI SysConfig |
| `vision/k230/three_color_blocks.py` | 图像采集、五色识别、背景色域过滤、标定和目标稳定判断 | K230 |
| `vision/k230/robot_link.py` | K230 与主控通信 | K230，与视觉入口放一起 |
| `tools/console.py` | 串口命令输入及示教参数恢复 | Windows 电脑 |
| `build/mspm0/robot1.out`、`robot1.hex` | 已编译固件 | 用兼容探针烧录 |

`coordinate_map.py` 及对应工具不是当前固定抓取点流程的必需文件。不要把旧 STM32/OpenMV 程序与本套混用。

> 2026-11-13：电脑控制台已改到 UART3 PA14/PA13，以适配照片中实际引出的 A14/A13。使用此接法前重新烧录本次固件；旧固件仍使用 PA10/PA11。

## 2. 接线速查

下面只画信号连接，电源接法必须同时阅读 [完整接线教程](wiring_v1.md)。所有设备断电后接线，TX/RX 交叉，GND 共地。

```text
K230 IO9  TX ─────────── MSPM0 PA22 RX
K230 IO10 RX ─────────── MSPM0 PA21 TX

MSPM0 PB6 TX ─────────── BusLinker UART RX
MSPM0 PB7 RX ─────────── BusLinker UART TX（先确认逻辑电平）
                         │ 三针总线
                         ├─ HTD-35H，ID 1，J3
                         ├─ HTD-35H，ID 2，J4
                         └─ HTS-21H，ID 3，J5 夹爪

MSPM0 PB18 ────────────── J1 底座舵机 S
MSPM0 PB19 ────────────── J2 第一俯仰关节舵机 S

MSPM0 PA14 TX ────────── 独立 USB-TTL RX → 电脑
MSPM0 PA13 RX ────────── 独立 USB-TTL TX → 电脑
MSPM0 PA2 ── 常开停止按钮 ── GND
各设备 GND ──────────── 公共地
```

MSPM0 与 K230 使用 3.3V 逻辑。BusLinker TX 电平未确认前，不直接接 PB7；若为 5V，使用合适的 UART 电平转换。BusLinker 的 UART `5V` 脚本方案不接。

电源分支：K230 用配套 5V Type-C 电源；MSPM0 首次用核心板 USB；两只 PWM 舵机用独立 6.0V 稳压支路；总线舵机经 BusLinker 使用与实物额定范围匹配的电源。具体电压、接口和容量检查见完整接线教程。共地不等于把正电源连在一起，舵机动力电不能从 MCU 引脚取。

总线 ID 要一次只接一只设置。MCU 接管 BusLinker 前拔掉 BusLinker USB，电脑调试另用 USB-TTL。普通 USB-TTL 不能烧录 MSPM0；烧录需支持 MSPM0G3507 的 SWD 探针，PA19 为 SWDIO、PA20 为 SWCLK。

## 3. 从零运行顺序

1. **烧录主控。** 舵机动力断开，用 TI UniFlash 和兼容探针烧录 `robot1.out` 或 `robot1.hex`，执行验证。完整步骤见 [烧录与测试](testing_v1.md)。
2. **连接电脑调试。** 安装 `pyserial`，执行 `python tools/console.py COM7`，将 COM7 换成实际端口。发送 `HELP`、`STATUS`，检查启动为未使能状态。按停止键，再发 `CLEAR` 验证停止输入。
3. **运行 K230。** 将 `three_color_blocks.py`、`robot_link.py` 放到板上 `/sdcard/`，保留配套 `libs`。在 CanMV IDE 运行视觉入口，先不覆盖开机程序。按 [视觉标定教程](../vision/k230/README.md) 标定五种颜色及工作台底色，最后设 `CALIBRATED = True`、`UART_ENABLED = True`。本版主控分拣红绿蓝，黄紫可在 K230 屏幕和控制台查看。
4. **读取舵机。** 设置三个 ID、接好总线并供电，`STATUS` 应显示 `online=1`。未在线先检查接线、电平、供电和 ID。
5. **单关节调试。** 支撑机械臂，先卸载 PWM 连杆，确认可接受的起始脉宽后发 `ARM 脉宽1 脉宽2`。再按教程小步 `JOG`，核对方向及机械限位。不能直接复制别人的起始位置。
6. **示教七个姿态。** 用 JOG 到位后分别执行 `TEACH HOME`、`TEACH APPROACH`、`TEACH PICK`、`TEACH LIFT`、`TEACH RED`、`TEACH GREEN`、`TEACH BLUE`。配置 `GRIP 打开值 闭合值`。逐段检查实际运动路径。
7. **保存实测参数。** `DUMP` 输出的 POSE/GRIP 行保存到文本文件。参数在 RAM 中，重启会丢失；用 `python tools/console.py COM7 --restore poses_measured.txt` 恢复，再单独使能。
8. **测试分拣。** 先空载分别执行 `SORT RED`、`SORT GREEN`、`SORT BLUE`，每次等 `DONE cycle`。验证后在固定点放方块测试。
9. **自动模式。** 输入 `AUTO`，回 HOME 后先保持工作区为空，再把一个方块放到标记点。每轮完成后先让视觉看到空场景，再上下一块。

默认抓取窗口是 640×480 画面中心 `(320,240)`，容差各 ±25 像素。摄像头在 HOME 姿态下，桌面固定抓取点必须与该窗口对应。移动摄像头、底座或抓取标记后，需要重新核对。

## 4. 编译和验证

在解压后的工程根目录打开 PowerShell：

```powershell
python -m pip install pytest ziglang pyserial
python -m pytest tests -q
python tools/test_firmware.py
python tools/build_firmware.py
python tools/package_v1.py
```

编译依赖 TI SDK、SysConfig 和 TI Arm Clang，安装路径及参数见 [烧录与测试](testing_v1.md)。ZIP 不包含完整 TI 工具链或 K230 配套系统镜像；K230 需要匹配当前板卡固件的 PipeLine 库。

## 5. 完成到什么程度

电脑测试及目标编译的结果见 [验证记录](validation_v1.md)。这些检查不代表实物已跑通。舵机电平、PWM 波形、供电容量、识别阈值、姿态和抓取效果仍需现场验证。

STOP/停止键会停止后续动作并保持动力，不是物理断电急停。初次动作应保持结构有支撑，并能切断舵机动力电源。
