# 每部分在哪个软件中编辑、运行

代码文件由助手直接创建/编辑；主控按 Keil5 工程组织，并用本机 Keil 编译。不是所有代码都在 Keil 里运行。

| 部分 | 编辑/打开的软件 | 实际执行位置 | 入口 |
|---|---|---|---|
| MSPM0 主控 C/H/汇编工程 | Keil µVision 5；普通编辑器也能改 C/H | MSPM0G3507 芯片 | `firmware/keil/robot_mspm0.uvprojx` |
| K230 视觉 Python | CanMV IDE K230 | K230 板上的 CanMV/MicroPython | `vision/k230/color_detection.py` |
| 电脑图形演练 | VS Code 等编辑器；Python 3 运行 | Windows 电脑 | `tools/打开无舵机演练.bat` |
| USB 下载工具 | Python 3 + PowerShell 7/.NET | 电脑，通过串口写入 MSPM0 | `tools/USB直接烧录_自动等待BSL.bat` |
| 板端串口检查 | PowerShell 7 | 电脑发送查询，MSPM0 回复 | `tools/烧录后检查串口.bat` |
| 三色板端模拟检查 | PowerShell 7 | 电脑发模拟命令，流程在 MSPM0 执行 | `tools/板端三色流程自检_不动舵机.bat` |
| C 协议/流程测试 | GCC/MinGW 编译，Python 3 调度 | 电脑，不连接硬件 | `python tools/run_pc_checks.py` |
| 文档 | VS Code、Markdown 阅读器、GitHub | 阅读用 | `README.md`、`docs/` |

## 1. Keil5：主控代码

完整解压整理包，打开 `firmware/keil/robot_mspm0.uvprojx`，选择 `MSPM0G3507_Bench`，按 F7 编译。不要仅复制 uvprojx，因为它还引用 `src`、`include`、`lib` 和 `vendor`。

当前电脑已安装 TI DFP `MSPM0G1X0X_G3X0X 1.3.1`；设备包安装程序不放进 GitHub 源码包。必要的 DriverLib/CMSIS 源码已在 `firmware/vendor/`，带原始许可和来源清单。

原固件用 Keil 5.24a / Arm Compiler 6.7 编译，0 错误 0 警告，已板端验证。TI 官方 Keil 流程要求 MDK 5.38a+ / Compiler 6.16+；在其他电脑使用新版编译器时，在工程设置里选择已安装的 Arm Compiler 6。升级编译器后要重新核验产物，不能假定 HEX 哈希仍相同。项目不依赖 SysConfig 自动生成步骤。

本板成功下载用的是 **Python/.NET USB BSL 工具**，不是 Keil 的 Load 按钮。普通 USB 数据线经板载 CH340 提供串口，不能把它当作 Keil 的 SWD 调试器。

## 2. CanMV IDE K230：摄像头代码

依次打开并运行 `camera_check.py`（检查画面）、`auto_calibrate.py`（现场阈值）、`color_detection.py`（识别）。程序实际在 K230 上执行，不能用电脑普通 Python 直接运行，因为它依赖 `media.sensor`、`media.display` 等板端模块。

这次仅收录已有文件，没有连接 K230、写入其文件或改其运行程序。`UART_ENABLED=False` 保持原样；真实木块阈值和主控 UART 联调仍待完成。归档的旧 PWM 试验脚本不在当前运行步骤内。

## 3. Windows：不连接板子的演练和测试

需要 Python 3（本机 3.12）及 MinGW GCC；图形界面还需要 Python 自带的 Tkinter。代码先查 `ROBOT_SIM_CC` 环境变量，再查 PATH 中的 gcc，最后兼容本机 Dev-C++ 安装路径。

在整理包根目录运行：

```powershell
python tools/run_pc_checks.py
python tools/robot_sim.py --demo
python tools/robot_sim.py
```

第一条运行纯电脑测试；第二条演练三色及异常情况；第三条打开窗口。都不打开串口。演练程序会生成 `tools/build/`，这些文件被 `.gitignore` 排除。

`tools/k230_sender.py` 不带 `--port` 时只打印测试帧。实际发送需要额外 3.3V USB-TTL 接主控视觉输入，且需要 `pyserial`；可安装 `requirements-pc-optional.txt`。不要将视觉测试帧发到主控调试 COM8 代替视觉 UART。

## 4. Windows：连接主控的工具

本机端口 COM8，应用波特率 115200 / 8N1；BSL 波特率 9600 / 8N1。一次只开一个串口工具。

主控当前已烧好，正常运行不按 BSL。串口复测和流程自检可以双击对应 BAT，动作输出仍关闭。普通终端运行示例：

```powershell
pwsh -NoProfile -File tools/check_bench_uart.ps1
pwsh -NoProfile -File tools/check_bench_flow.ps1 -Port COM8
```

需要重新烧录时才运行下载 BAT；等 READY 后按住 BSL → 短按并松开 RST → 等 1 秒 → 松开 BSL，无需回车。程序只擦写 MAIN 前 16KiB，不改 NONMAIN。完整流程和首次 CRC 异常的处理见 [USB 下载说明](testing/USB_BSL下载准备.md)。

下载器有固定固件哈希检查。重新编译或更换电脑后，先审查 HEX 地址、向量和动作开关，再更新 `tools/uniflash/config.json` 中的 `firmware_sha256`；这里沿用旧目录名，但本包不依赖 UniFlash 安装。
