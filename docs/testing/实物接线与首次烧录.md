# MSPM0G3507 实物接线与首次烧录

更新于 2026-11-03；对应 `robot bench v2.1`。基础固件已在本板运行，暂不启用实际动作。

## 当前接法和入口

只接 **电脑 USB → 核心板底部 USB-C**。这根线同时供电和连接 CH340 串口。COM8 / 115200 / 8N1 用于应用调试，不需要 ST-Link 或外置 USB-TTL。

- 复测串口：`tools/烧录后检查串口.bat`。
- 复测三色流程：`tools/板端三色流程自检_不动舵机.bat`。
- 查看运行状态：`tools/打开COM8串口查看.bat`（只读）。
- 只有需要重新下载时才用 `tools/USB直接烧录_自动等待BSL.bat`。完整步骤见 [USB 下载说明](USB_BSL下载准备.md)。不要同时打开多个串口工具。

本机 Keil 5.24a / Arm Compiler 6.7 编译 0 错误 0 警告；本次固件也已板端验证。TI 官方支持要求 MDK 5.38a+ / Compiler 6.16+；在线 SWD 调试兼容性未验证。本次采用自建 Python/.NET BSL 下载器，不是 Keil 的 Load 按钮，也不是 TI UniFlash 成功下载。

## 照片对应的接口

照片中间的长条板为核心板，底部 USB-C 用于本轮逻辑供电及板载 CH340 串口；外围是带插座、电源端子和按键的扩展板。串口功能已通过实际枚举和 BSL 响应验证；电源灯亮本身仍不能证明程序已下载。

板上 `A10` 就是代码里的 `PA10`，`A19` 就是 `PA19`。**接到标有这些信号名的可用排针/引出点，别数芯片脚，也不要凭线的颜色猜。** 如果丝印被挡住，先确认核心板引脚图或拍清晰近照；不要猜白色插座、顶端四针口的排列。

板上印的 `UART3` 不代表本程序的调试串口。本程序调试串口固定使用下面的 A10/A11。

## 第一步：供电

1. 断开电池、扩展板 IN/OUT 外接线、所有舵机及 K230；先在断电状态下接信号线。
2. 只用核心板底部 USB-C 接电脑/正常 5V USB 电源供电。本次无需下载器，不同时再往 3V3 或 5V 灌入另一份电源。
3. 有万用表时，测核心板 `3V3` 对 `GND` 约为 3.3V，再开始连接调试器。

照片上输入端明确写的是 **IN 5–12V**。标称 12V 电池满充可能为 12.6V，超出该丝印范围，不能据此直接接入。OUT 的电压和电流能力尚未证实，先保持空着；它不是已经确认的机械臂供电口。舵机动力供电后续单独确认。

## 第二步：通用 SWD 下载线（紫色 ST-Link 请看专项接线文档）

| 主控板丝印/信号 | 兼容下载器端 | 说明 |
|---|---|---|
| A19 / PA19 | SWDIO / DIO | 调试数据 |
| A20 / PA20 | SWCLK / CLK | 调试时钟 |
| GND | GND | 共地 |
| 3V3 | VTref / Vref（若有） | 电压检测参考输入，不是再次给板供电 |
| RST / NRST（若有引出） | nRESET / RST | 建议接；不要误接 BSL 按键 |

若下载器只有标着 `3V3` 的供电脚、没有 VTref，必须先看其说明；板已由 USB 供电时，不把两路电源直接并联。没有引出的 RST 不要向芯片引脚临时搭线。

SWD 引脚依据 [TI MSPM0G3507 数据手册](https://www.ti.com/lit/ds/symlink/mspm0g3507.pdf)，表中名称不规定下载器或扩展板连接器的针序。

## 第三步：调试串口（与下载器是两种功能）

本板先使用已连接的 USB 数据线和 COM8，无需另接线。下面仅列出外置 **3.3V 逻辑电平** USB-TTL 的备用接法；使用外置模块前须确认与板载 CH340 不发生输出冲突，不同时把两个 TX 接到 A11。普通 ST-Link 不默认带 UART。

| 主控板 | USB-TTL |
|---|---|
| A10 / PA10，UART0_TX | RXD |
| A11 / PA11，UART0_RX | TXD |
| GND | GND |
| 5V、3V3 | 不接，板已由 USB 供电 |

串口助手设置：**115200，8 数据位，无校验，1 停止位，无流控；ASCII 文本发送；结尾 CRLF 或 LF**。只有 CR 不会执行命令。不要接 RS232 电平转换器；模块的“3.3V 电源输出”也不一定代表 TXD 已是 3.3V，应核对模块逻辑电平。

## 第四步：打开并编译工程

交付文件夹 `MSPM0_FirstBringup_20261101` 内：

| 文件 | 用途 |
|---|---|
| `firmware/keil/robot_mspm0.uvprojx` | 双击打开 Keil 工程 |
| `firmware/src/main.c` | 主程序、串口命令入口 |
| `firmware/src/board_mspm0.c` | 串口、PWM、时钟初始化 |
| `firmware/include/app_config.h` | 两个动作开关均为 0，首次不要改 |
| `firmware/src/robot_config.c` | 未标定的关节/姿态参数 |
| `firmware/keil/Objects/robot_mspm0.hex` | 已编译固件，仅含 MAIN Flash |
| `firmware/keil/Objects/robot_mspm0.axf` | 带调试信息的程序 |
| `device_pack/*.pack` | TI 官方设备包原始安装文件，保留原许可 |
| `build_report.txt` | 本次编译、测试和 HEX 地址检查结果 |

完整解压到普通文件夹后打开工程，不要在 ZIP 内直接打开，也不要只复制 `.uvprojx` 一个文件。可用英文路径，例如 `C:\Robot\MSPM0_FirstBringup_20261101`。

本机已经装有 `TexasInstruments.MSPM0G1X0X_G3X0X_DFP 1.3.1`。若新 Keil 安装位置看不到该设备，在 Pack Installer 导入随包 `.pack`，按其安装界面处理许可。

选择目标 `MSPM0G3507_Bench`，在 Options for Target → Target 确认器件 `MSPM0G3507`。本工程为 Arm Compiler 6，升级后将编译器选为已安装的 **6.16 或更高版本**，不要切到 Compiler 5。按 F7，确认 `0 Error(s), 0 Warning(s)`。

## 第五步：下载

**当前采用 USB BSL：** 按 [USB BSL 下载准备](USB_BSL下载准备.md) 使用项目自建下载脚本。不要在 Keil 中将 CH340 选作 CMSIS-DAP，不点 Factory Reset。

以下仅供以后拥有兼容 SWD 下载器时使用：

1. Options for Target → Debug → 选择 `CMSIS-DAP Debugger`；这不是 `ST-Link Debugger`。
2. Settings → 选择实际下载器，Port 选 **SWD**；第一次可选较低的 100kHz。应能读到 SWD 目标，不能识别时先查供电、DIO/CLK/GND 及版本，不要用擦除保护区来试错。
3. Flash Download 只保留 **MSPM0G1X0X_G3X0X_MAIN_128KB** 算法，Start `0x00000000`，Size `0x00020000`。不要选择 STM32 算法或 NONMAIN 算法，不改 BCR/BSL 安全配置。
4. 使用 Erase Sectors、Program、Verify；确认后按 Load 下载。成功后运行程序，或退出调试后按一次 RST。
5. 成功依据是下载/校验完成，以及下一步实际收到串口回复；编译成功不等于烧录成功。

## 第六步：逐条验证

复位后串口应看到版本行：

```text
MSPM0G3507 robot bench v2.1 | SYSOSC 32MHz | UART 115200 8N1
DEBUG UART0: PA10=TX PA11=RX | SWD: PA19=DIO PA20=CLK
```

约每秒会有一行 `STATUS`；`ms` 应递增，未接 K230 时 `online=0 target=NONE` 正常，`motion=0 armed=0 bus=0` 表示动作关闭。

| 依次发送（每条加回车换行） | 预期 |
|---|---|
| `PING` | `PONG MSPM0G3507`，说明收发都通了 |
| `HELP` | 打印可用命令 |
| `STATUS` | 立即打印主控状态 |
| `JOINTS`、`POSES` | 显示待标定参数，未知值不会变成动作 |
| `START RED` | 模拟准备、靠近、夹紧、抬起、移至放置区、松夹、返回；约 7 秒结束 |
| `FLOW` | 看到 `DONE`，红色对应 LEFT（仅流程标签） |
| `RESET` | 结束后回到空闲；不是硬件复位 |
| `START GREEN` / `START BLUE` | 分别演练 CENTER / RIGHT；每轮结束后先 RESET |

`SIM_ACK` 是程序自己产生的模拟完成信号，不是舵机反馈。`START` 不会驱动真实机械臂。关节位置、到位反馈和相机到机械臂的坐标转换仍未标定或实现。

没有串口数据：先确认下载及校验成功、关闭下载工具对串口的占用，打开 COM8 / 115200 并只按一次 RST（不按 BSL）。外置串口方案才需要额外核对共地和 TX/RX。能收到 STATUS 但 PING 没响应时，先检查发送结尾是否为 LF 或 CRLF。没有板载 LED 引脚图，所以本工程没有指定 LED 闪烁测试；电源灯亮只能说明有供电。
