## 异常与处理

早期旧线出现 USB Code 43、SetCommState 错误和写超时，曾在 MAIN 擦除、至少写入 2KiB 后中断。已备份原 CH340 3.9.2024.9，切换到本机已有且签名有效的 3.3.2011.11；旧线仍失败。更换 USB 线后完整写入成功。不能仅凭这些对照认定驱动或旧线是唯一原因。

完整写入后的首次即时 CRC 为 `0BE69001`，与期望不符，工具拒绝启动应用。用户重新进入 BSL 后，未改写 Flash，分段及整段均核验正确。即时校验异常根因尚未确定。本轮验收依据的是后续实际匹配的校验和应用测试，不是忽略第一次错误。

诊断尝试读取 MAIN，设备返回读回禁用（0x09）；没有修改保护策略，改用 TI 支持的 CRC 校验。因此本次是 CRC 校验，**不是逐字节读回**。

发现 ROM 已建立串口会话后再收 CONNECTION 命令会返回 ACK 加 UNKNOWN_COMMAND（0x06）；下载器此前只消费 ACK，导致下一条回复错位。已按实测报文消费并验证该完整回复，新增离线测试。此修正解决会话同步，不作为首次 Flash CRC 差异的根因结论。

自建下载器 10 个离线测试通过，覆盖 TI 报文向量、损坏响应、MAIN 边界、密码失败停止、写失败停止、CRC 不匹配拒绝、只校验不写入，以及新旧连接会话。此前电脑端 65 项协议断言和 134 项流程断言通过；本轮未修改固件源码，沿用原 0 错误 0 警告编译产物。
