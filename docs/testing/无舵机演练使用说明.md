# 无舵机演练使用说明

即使不连接主控板和舵机，也可以在电脑上验证机械臂流程。**不需要连接 K230，也不读取摄像头或打开串口。**

## 打开窗口

双击 `tools/打开无舵机演练.bat`，或者在项目目录执行：

```powershell
python tools/robot_sim.py
```

窗口的 C 后端直接编译 `firmware/src/robot_config.c`、`robot_workflow.c` 和 `robot_console.c`，与 Keil 固件使用相同源文件，不是另一套 Python 动作逻辑。首次启动需要本机现有 MinGW64 GCC；后续按源码哈希缓存 DLL。源码修改后会重新生成 DLL；已打开的窗口需要关闭再打开才能加载新版本。

Python 使用本机 64 位 Python 3.12 和自带 Tkinter，不需要额外 pip 包。此电脑的编译器路径在 `tools/build_robot_sim.py` 中；换电脑可设置环境变量 `ROBOT_SIM_CC` 指向 MinGW64 的 `gcc.exe`。

## 正常演练

1. 选择“自动演练”，点红、绿或蓝按钮。
2. 七个步骤依次推进：准备 → 靠近目标 → 夹紧 → 抬起 → 移到放置区 → 松夹 → 返回。
3. 放置区映射为红色左区、绿色中区、蓝色右区。这是流程标签，尚未对应物理位置。
4. 每步持续约 1 秒，由模拟器产生 `SIM_ACK`。最后显示“演练完成”。
5. 点“复位”回到等待状态，再选另一种颜色。复位只清理软件状态，不移动任何部件。

“暂停”会冻结当前步骤的活动计时，“继续”接着剩余时间执行。“中止”立即结束本次演练，不能用“继续”接回，必须复位后重启。运行或暂停期间不接受第二次启动，也不能直接复位跳过中止。

## 故障与手动演练

- **模拟超时**：在自动演练期间点击，停止生成模拟回执；当前步骤活动时间达到 3000ms 后进入故障，不再推进。
- **模拟失败**：立即进入故障，包括已暂停的情况。必须复位才能再次开始。
- **手动确认**：在等待状态切换；每一步点“确认本步完成（模拟）”，3 秒内未确认会超时。需要长时间查看时先暂停。
- 每一步都有递增的 `ticket`。手动确认必须携带当前 ticket，旧步骤或上一次演练的回执会被拒绝；复位不会重置 ticket。
- 电脑休眠或界面长时间无法处理事件，恢复时可能触发超时，这是超时检查的预期结果。

本次的暂停只暂停模拟计时；未来真实机械臂暂停时的制动、保持扭矩、路径恢复等还未实现，不能把模拟行为直接当成物理行为。

## 参数页与标定文件

“关节与位置”页展示当前 C 配置，所有位置都显示待标定。关节表在 `firmware/src/robot_config.c`：

| 关节 | 拟定 ID | 当前状态 |
|---|---|---|
| 底座 BASE | 1 | 未确认 ID、未标定 |
| 肩关节 SHOULDER | 2 | 未确认 ID、未标定 |
| 肘关节 ELBOW | 3 | 未确认 ID、未标定 |
| 夹爪 GRIPPER | 4 | 未确认 ID、未标定 |

方向=0、零位/限位=-1、速度上限=0 表示未知。不能把这些值用于运动。ID 是计划表，没有写到设备中。配置检查可发现 ID 重复、未确认 ID、方向不合法、限位/零位不一致、未知速度及无效姿态。

姿态表包含准备、靠近、夹紧、抬起、三色放置、松夹；返回复用准备姿态。各姿态的关节目标和运动时间均未填写。演练的 1000ms 由独立模拟计时控制，**不代表真实舵机速度或到位时间**。

参数表暂为源码配置，窗口只读；没有实现写 Flash 保存、自动修改舵机 ID 或标定命令。现有 `MOVE` 单舵机测试仍使用原来的临时测试限制，尚未接入这张关节标定表。

## 与主控共用的命令

| 命令 | 含义 |
|---|---|
| `START RED` / `START GREEN` / `START BLUE` | 开始对应颜色的纯模拟演练 |
| `PAUSE` / `RESUME` | 暂停 / 继续 |
| `STOP` | 中止演练；不是硬件急停 |
| `RESET` | 空闲或结束/故障后清理状态 |
| `FLOW` | 查看演练状态、步骤、计时和 ticket |
| `JOINTS` / `POSES` | 查看关节 / 姿态参数 |
| `SIM AUTO` / `SIM MANUAL` | 空闲时切换回执模式 |
| `ACK 5` | 手动模式确认 ticket=5 的步骤（数字需使用当前值） |
| `SIM STALL` / `SIM FAIL` | 模拟没有回执 / 动作失败 |

这些命令也已接入固件 UART0 调试入口。固件中手动硬件 ARM 与演练互斥；演练运行、暂停或结束未复位时，ARM/PWM/MOVE 会被拒绝。`DISARM` 同时中止正在进行的演练，但物理急停仍需独立设计。

## 自动检查和记录

```powershell
python tools/robot_sim.py --test --demo
```

- `--test`：运行 134 项 C 断言检查，覆盖参数校验、三色完整路线、重复启动、暂停计时、结束状态、过期回执、超时、失败、毫秒计时回绕及命令校验。
- `--demo`：通过实际共享 DLL 接口执行三色路线、暂停/继续/中止、超时和参数查询，生成 `docs/testing/无舵机演练日志.txt`。
- Keil 工程包含同一套流程源码；编译验证不等同于板端验证。

此版本没有逆运动学、轨迹插补、碰撞检查、实物到位判断或夹持成功检测。后续需要真实 ID/限位、连杆尺寸和供电信息，再设计硬件执行与反馈接口。流程代码当前没有硬件执行入口，即使把原手动动作开关改为 1，`START` 仍只演练。
